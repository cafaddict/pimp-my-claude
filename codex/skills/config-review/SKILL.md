기본은 읽기 전용 보고서다. 사용자가 `--apply` 또는 수정 요청으로 승인한 범위만 변경한다.
삭제·이동이 승인 범위에 없으면 구체적인 변경안을 먼저 제시한다.

1. **범위**: 전역 `{{CODEX_DIR}}/AGENTS.md`, `config.toml`, `hooks.json`, `agents/`,
   `{{SKILLS_DIR}}/`와 프로젝트의 `AGENTS.md`, `.codex/`, `.agents/skills/`를 살핀다.
   `--project <경로>`가 있으면 그 프로젝트로 한정한다. 중첩 `AGENTS.md`의 적용 범위를 보존한다.
2. **측정**: 파일별 줄 수·수정 시각·명시 경로와 실제 존재 여부를 확인한다.
   Markdown 링크와 리소스 참조를 실제 경로로 해석한다. `@path`를 자동 import라고 가정하지 않는다.
   hook은 `$guide`처럼 JSON과 TOML의 실제 바인딩으로 확인하고, config의 비밀 값은 출력하지 않는다.
   AGENTS.md 는 전역에서 `AGENTS.override.md`·`AGENTS.md` 중 처음 비어 있지 않은 파일 하나, 프로젝트 루트부터
   현재 디렉터리까지 이어 붙인다. 합계가 `project_doc_max_bytes`(기본 32 KiB)에 닿으면 뒤 파일은 빠진다.
3. **판단**: 끊긴 참조, 충돌, 중복, 불필요하게 긴 지시, 오래된 내용을 근거와 함께 분류한다.
   절차형 지시는 skill로, 지속 규칙은 적용 범위에 맞는 `AGENTS.md`로 옮길 후보로 제안한다.
   사용 로그가 없으면 skill이 쓰이지 않는다고 단정하지 않는다.
   지시문 자체는 아래 '프롬프트 패턴' 기준으로 본다.
4. **보고**: `file:line`, 인용, 패턴, 이유, 확신도(High/Medium/Low), 조치(remove/rewrite/flag)와
   최소 변경안을 diff 로 제시한다. Low 와 flag 는 diff 에 넣지 않는다. 문서 길이만으로 삭제를 권하지 않는다.
5. **적용**: 기존 승인 범위의 항목만 고치고 관련 형식·설치 검사를 실행한다.
   hook 개발은 `$harness`, 반복 교훈 반영은 `$vault-promote` 절차를 참고한다.
   이 저장소에서 배포한 파일이면 소스 checkout `{{SOURCE_DIR}}`를 먼저 수정하고 문서를 갱신한다.

### 프롬프트 패턴 (그 파일을 읽는 모델 기준)
대상 모델은 파일을 읽는 모델이다. custom agent TOML 에 `model` 이 있으면 그 모델 기준으로 본다.
- **압박 표현**: 이유 없는 `반드시`·`절대`·CRITICAL·굵은 경고, 반대로 진짜 요구에 붙은 "가능하면". 지금 모델은 지시를 글자 그대로 따라 과하게 반응한다 → 평범한 말과 이유로 바꾼다.
- **모델이 알아서 하는 일**: "단계별로 생각하라", 요청을 내부 구조로 바꾸라는 지시, 판단 작업에 강제한 단계 순서나 개수(가설 최소 N개) → 목표와 지켜야 할 제약만 남긴다.
- **화석**: 옛 모델용 우회, 컨텍스트 % 같은 수치 규칙, 고정된 옛 모델 ID, 날짜·사건이 붙은 이력, "이제는 ~" 처럼 이전 버전과 비교하는 문장 → 지금 규칙만 쓴다.
- **실물과 다른 내용**: 설치되지 않은 도구·MCP 를 나열한 산문, 없는 경로·명령, Codex 가 읽지 않는 파일명(`project_doc_fallback_filenames` 에 없는 이름)이나 필드.
- **소비자 없는 지시**: 아무도 읽지 않는 출력 섹션, 스스로 "강제되지 않는다"고 밝힌 규칙 → hook 이나 sandbox·승인 설정으로 옮기거나 지운다.

남기는 것: 작성자만 아는 맥락과 제약의 이유, 되돌리기 어려운 작업의 정확한 절차, 실제로 재발한 실패를 막는 금지, description 의 트리거 문구, 내용이 일치하는 중복. 길이만으로는 지우지 않는다.
충돌은 두 위치를 인용하고 git 이력으로 어느 쪽이 최신인지 정한다. 이력으로 정할 수 없으면 고치지 말고 사용자가 정할 질문으로 보고한다. 프로젝트 파일을 근거로 전역 파일을 고치지 않는다.

보고만 했으면 마커도 쓰지 않는다. 사용자가 점검 완료 기록을 요청했을 때만 vault 밖의
`{{CODEX_DIR}}/.config-review-stamp`를 갱신한다. 자동 실행 hook이나 반복 점검을 추가하지 않는다.
