PR 번호가 있으면 `gh pr view`와 `gh pr diff`로 의도와 변경을 읽고, 없으면 현재 diff를 읽는다.
먼저 리뷰할 기준과 범위를 고정해 모든 리뷰어가 같은 변경을 보게 한다.

1. `code-reviewer` subagent 3개에 보안, 성능, 정확성·테스트 관점을 각각 맡긴다.
   범위, diff, 관련 파일과 계약을 전달하고 코드·설정 수정과 리뷰 게시를 맡기지 않는다.
2. 모든 결과를 기다린 뒤, 각 finding을 다른 리뷰어에게 전달해 재현·반박을 맡긴다.
   직접 agent 간 통신에 의존하지 않고 메인 agent가 근거와 반론을 전달한다.
3. 재현 조건, 호출 경로, 영향과 반대 근거를 대조해 중복을 합치고 근거 없는 주장은 철회한다.
4. 확인된 문제를 중요도순으로 `file:line`, 발생 조건, 영향, 검증 결과와 함께 보고한다.
   검증하지 못한 가설은 별도로 표시한다. 합의만으로 문제를 확정하지 않는다.

세션의 동시 실행 한도를 지킨다. custom agent가 없으면 같은 역할 지시를 일반 subagent에
전달하고, subagent 도구가 없으면 세 관점을 순서대로 검토해 그 제한을 알린다.
재사용할 교훈은 저장을 제안하고, 사용자가 요청·승인한 경우에만 메인 agent가 `$vault-note`로 기록한다.
