## 리뷰 컨텍스트

- 변경사항: !`gh pr diff $0 2>/dev/null || git diff`
- PR 설명: !`gh pr view $0 2>/dev/null || echo "PR 없음 — git diff 기반 리뷰"`

## 리뷰 프로토콜

### 1. 변경 범위 파악
- 변경된 파일 목록과 변경 규모 정리
- PR 설명/커밋 메시지에서 의도 파악

### 2. 정확성 검토
- 로직이 의도대로 동작하는가?
- 엣지 케이스 처리가 되어있는가?
- 에러 핸들링이 적절한가?

### 3. 보안 검토
- 인젝션 (SQL, command, XSS) 가능성
- 인증/인가 우회 가능성
- 민감 데이터 노출 (로그, 에러 메시지)

### 4. 성능 검토
- 불필요한 연산, N+1 쿼리, 메모리 누수
- 알고리즘 복잡도가 적절한가?
- 대량 데이터에서의 동작

### 5. 테스트 커버리지
- 변경된 로직에 대한 테스트가 있는가?
- 엣지 케이스 테스트가 포함되어 있는가?
- 테스트가 누락되었다면 어떤 테스트가 필요한가?

### 6. 발견 사항의 근거 확인
- 문제가 발생하는 호출 경로와 요구사항을 확인한다. 새 변경으로 생긴 문제인지, 기존 문제인지 구분한다.
- 중요한 정확성 문제는 최소 입력과 기대값·실제값으로 설명한다. 가능하면 기존의 좁은 테스트나 부작용 없는 작은 재현으로 확인한다.
- 발견을 반박할 조건도 확인한다. 호출자의 입력 검증이나 명시된 계약이 문제를 막는다면 그 주장을 철회하거나 범위를 좁힌다.
- 코드를 고치거나 의존성을 설치하지 않는다. 실행이 외부 상태를 바꾸거나 권한이 부족하면 정적 근거와 미검증 이유를 보고한다.
- 리뷰 범위 안에서 필요한 확인만 한다. 같은 검사를 반복하거나 별도 에이전트를 자동 실행하지 않는다.

## 출력 형식

각 이슈를 아래 형식으로 정리:

**[Critical]** `파일:라인` — 설명
> 수정 제안

**[Warning]** `파일:라인` — 설명
> 수정 제안

**[Suggestion]** `파일:라인` — 설명
> 수정 제안

마지막에 전체 요약 한 문단.
확인된 문제와 추가 확인이 필요한 가설을 구분한다. 확인된 문제가 없으면 없다고 쓰고,
실행한 검증과 남은 한계를 적는다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
